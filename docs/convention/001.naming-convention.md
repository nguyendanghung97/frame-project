# Naming convention

Rules below apply to **new** code across frontend packages; legacy paths may differ until refactors align them.

## Singular names

File and folder names must use **singular** nouns so each path reads as one module or area, not an unspecified collection—prefer `case_notebook`, `DoctorCard.tsx`, and `formatPhone.ts` over plural stems such as `case_notebooks` or `DoctorCards.tsx`.

Strongly established conventions at root (./src) folder such as: ./components, ./styles, ./hooks, ./contexts, ./stores, ./utils, ./types, ./fixtures, ./shims, etc. are exceptions.

## Folders

**snake_case only.** Directory names use lowercase ASCII letters and digits; separate words with **one underscore** (`case_notebook`, `shift_entry`, `shared_from_provider`). A single segment without underscores is fine when one word is enough (`utils`, `zoom`). Do not use **kebab-case**, **camelCase**, or **PascalCase** in folder names.

Exception: conventional tooling folders such as **`__tests__`** / **`__mocks__`** (leading double underscore) may remain as established by the ecosystem.

## TypeScript / TSX

- **`*.tsx` → PascalCase** — any module whose main export is a React component (including pages).
- **`*.ts` → camelCase** — hooks, utilities, types, stores, config helpers, and other non-component modules.
- **`index.ts`** stays lowercase (barrels only).

Ambient typings use **`*.d.ts`** with the same **camelCase** stem as the library they describe when there is a single obvious name (`ringcentral-embeddable.d.ts`).

Prefer one primary component per file; name the file after that export when practical. Avoid generic names like **`test.tsx`** in production trees—use **`*.test.tsx`** or **`__tests__/`** (see Tests).

## CSS files

**Location.** Keep all first-party stylesheets for a package under that package’s **`styles`** directory—typically **`src/styles/`** alongside other `src/` trees (`components`, `pages`, etc.). Do not add new `.css` files next to components or elsewhere under `src/` unless an external tool forces it; migrate strays into **`src/styles/`** when touching them.

All stylesheet filenames are **kebab-case**, including globals and CSS Modules:

- `entry.css`, `layouts.css`
- `doctor-card.module.css` (pair with `DoctorCard.tsx`; the file name does not need to mirror PascalCase)

Use **`.module.css`** only for modular styles; same kebab-case rule applies.

## CSS class names

**Semantics.** Choose class names that reflect **meaning**—structure, role, or domain—not one-off presentational labels tied to a single layout snapshot, so styles remain understandable when visuals change.

**Tailwind.** When authoring rules in CSS (including CSS Modules under `src/styles/`), prefer **Tailwind CSS `@apply`** to compose utility classes into named selectors instead of spelling out the same declarations by hand.

Use **lowercase letters only** in class selectors and in `className` strings—no uppercase (`A–Z`). For multiple words, join with **hyphens** (**kebab-case**), e.g. `.case-entry`, `.shift-selector-v2`. Avoid camelCase, PascalCase, and uppercase BEM-style tokens in new styles.

## Tests

Use **`*.test.ts`** / **`*.test.tsx`**, optionally under **`__tests__/`**. Use the same stem as the module under test (`formatPhone.test.ts`, `DoctorCard.test.tsx`). Do not commit vague **`test.ts`** / **`test.tsx`** scratch files under **`src/`**.

## Quick reference

| Asset | Rule |
|-------|------|
| File / folder meaning | singular nouns ([Singular names](#singular-names)) |
| Folder | snake_case only (see exceptions for `__tests__`, etc.) |
| `.tsx` | PascalCase |
| `.ts` | camelCase (`index.ts` exception) |
| `.css` / `.module.css` | under `src/styles/`; kebab-case filenames |
| CSS class | semantic names; Tailwind `@apply` in stylesheets; lowercase kebab-case |
| Tests | `*.test.ts(x)` or `__tests__/` |
